# Build Roadmap

This project is built in nine phases, each one a working, demoable product on its own. The original plan had six; three more were added — two before scale-out once the project's scope grew to include public discovery and a UI pass, and a final one for advanced sketching tools.

- [x] **Phase 1 — Canvas + sync.** Multiplayer drawing/shapes/move, live cursors, presence. Single server instance, in-memory, no accounts yet. Shapes sync field-by-field (nested `Y.Map` per shape), so concurrent edits to different fields of the same shape both survive instead of one clobbering the other — verified with 3 simulated concurrent clients via the `multiplayer-sim-tester` subagent. Selection + delete (Delete/Backspace) and window-resize handling included.
- [x] **Phase 2 — Auth + friends + boards.** Login via Better Auth (email/password only — Google/GitHub OAuth was wired up in an earlier pass, then deliberately dropped: unnecessary complexity for a portfolio project, not a real product needing every sign-in option), a dashboard of your boards, adding friends by email, and inviting a friend to a specific board as collaborator or viewer. PostgreSQL via Docker from this point on. The centralized `authorization/boardAccess.ts` role check now gates both the REST API and the Yjs sync connection (via a short-lived signed "sync ticket") — verified with real HTTP requests and live Hocuspocus connections that a viewer's write is actually discarded server-side, not just hidden in the UI.
- [x] **Phase 3 — Chat.** DMs and group chats between friends, with typing indicators, scroll pagination, unread indicators, friendship-gated sending (disabled once unfriended, history preserved), per-user clear-history and delete-message, and WebSocket reconnect handling — verified end-to-end in the browser. Note to resolve when Phase 5 is designed: a board's live/broadcast chat needs to reconcile with this — likely a board-scoped chat is just a group chat whose membership mirrors `BoardMember`, not a separate system.
- [x] **Phase 4 — Video calls.** Camera/mic while sketching together, via a self-hosted LiveKit server. Role-gated at the token layer (`canPublish` derived server-side from board role, never client-controlled) — a viewer's client auto-connects subscribe-only whenever a collaborator/owner is actually in a call and auto-disconnects the moment none remain, with no manual Join Call control of their own. Floating, draggable, resizable call strip (client-side-only position/size, never synced). Verified end-to-end in the browser across owner/collaborator/viewer roles, including muted-state propagation and losing/regaining board access mid-call. Also closed a pre-existing Phase 1 gap found during this phase's testing: board canvas content is now persisted to Postgres (`Board.content`) instead of living in the Hocuspocus in-memory Y.Doc only.
- [x] **Phase 5 — Anonymous viewer links.** A shareable, read-only link (`/watch/:shareToken`) to watch a board's canvas, chat, and call — no account required. Chat mirrors real Twitch behavior: a **logged-in** viewer can post in chat (just not touch the canvas or publish media), while a fully **anonymous** link viewer is read-only on everything, chat included, capped server-side at viewer role via the same `boardAccess.ts` check extended with a share-token fallback. Verified with the `multiplayer-sim-tester` subagent (anonymous visitor strictly read-only with zero persisted chat rows; logged-in non-member can chat but stays capped at viewer) and a full manual browser walkthrough (share/regenerate link, incognito anonymous + non-member viewers, call auto-join, link revocation).
- [x] **Phase 6 — Home page (public board discovery).** A Twitch-style public landing page at `/`, replacing the old dashboard redirect, that recommends boards to anyone — logged in or fully anonymous — sorted by live viewer count, then total views, then recency. Boards are public and their watch link auto-enabled by default (an owner can flip a board to "Private" to unlist it from Home, though a private board's watch link still works for anyone who has it). Live viewer counts come from Hocuspocus's existing connection tracking; total views are a persisted per-board counter, incremented once per non-owner watch session. Design: `docs/superpowers/specs/2026-07-27-home-page-design.md`. Found and fixed a real bug during verification: view counting was originally wired to Hocuspocus's `onConnect` hook, which fires before authentication resolves the connection's role, so the owner's own connection was always miscounted as a view — fixed by switching to the `connected` hook, which fires after role resolution. Verified with the `multiplayer-sim-tester` subagent (real concurrent Hocuspocus WebSocket connections confirming live-viewer-count tracking and owner-exclusion) and a full manual browser walkthrough (Home page rendering, Share dialog's public/private toggle in both directions, a real non-owner view incrementing the count live). A final whole-branch review additionally closed a latent `shareToken`-null hole, added the missing `asyncHandler` wrapping on the new public route, added error/retry handling to the Home page's polling hook, and removed an owner-email fallback that could leak on the public endpoint.
- [x] **Phase 7 — UI overhaul.** A visual design pass across all 8 routes (Home, Log in, Sign up, Dashboard, Friends, Messages, Board, Watch), implementing the "Pale Cork" design system: a token layer (`client/src/styles/tokens.css`) of colors/type/radii/shadows/spacing, self-hosted Google Fonts (Ephesis wordmark, Patrick Hand headings, Inter body), a "Two Hands" SVG logo, and shared UI primitives (`client/src/ui/`: Button, Input, Modal, Avatar, StickyNote, PaperBar, SegmentedToggle) replacing the app's original all-inline-style approach with CSS Modules. UI-only — no data-model changes; the functional 10-color presence palette (`presenceColors.ts`) is untouched, and on-canvas content (shapes, remote cursors) is still styled via Konva shape props, not CSS. Also wired the `penColour` toolbar swatches into real shape stroke color, added tool keyboard shortcuts (V/R/O/L/P/T/N, Esc), and gave the board chat panel a slide-over layout under ~1100px. Deliberately did not add: a sticky-note canvas tool, canvas pan/zoom, animated cursor tweening, loading shimmers, or a toast system — those are new capabilities beyond a visual pass, not implied by "make existing screens look intentional."
- [x] **Phase 8 — Scale-out.** Redis now backs the three pieces of state that used to live only in one server process's memory: Hocuspocus's Yjs sync (`@hocuspocus/extension-redis`), chat delivery (a Redis-backed swap into the pub/sub interface built swappable back in Phase 3), and live viewer counts (a Redis sorted set with heartbeat-refreshed, self-expiring entries, replacing a read of Hocuspocus's local in-memory connection list). Better Auth's sessions needed no Redis cache — they were already Postgres-backed and correctly shared. The whole stack — client, 2 server instances, nginx, Redis, Postgres, LiveKit — runs via `docker-compose up`, with nginx round-robin load-balancing the two server instances and no sticky sessions, safe because of the Redis-backed state above. Verified with the `multiplayer-sim-tester` subagent (two simulated clients connected directly to each instance, bypassing nginx, confirming Yjs edits converge, chat messages deliver, and live viewer counts combine correctly across instances) and a manual two-tab browser walkthrough through nginx confirming both instances actually handled traffic. Found and fixed a real bug during the manual walkthrough: the client container's nginx (`client/Dockerfile`) had no SPA fallback, so a hard navigation to a client-side route (e.g. the post-signup redirect to `/dashboard`) 404'd — fixed by adding `client/nginx.conf` with a `try_files ... /index.html` rule.
- [x] **Phase 9 — Advanced sketching tools.** The final phase: bringing the canvas itself much closer to a real creative tool (Photoshop-style customization), well beyond the original hardcoded stroke color/width and single-shape selection. Split into three ordered sub-phases:
  - [x] **9a — Brushes & strokes.** A drawing-options bar (color/width/opacity, applying to every shape type, not just the pen), brush presets (pencil/marker/highlighter/eraser) for the freehand tool, freehand input smoothing (distance-based point sampling, independent of Konva's existing curve tension), and per-user undo/redo via `Y.UndoManager` scoped to a local-only transaction origin — so Ctrl+Z never undoes a collaborator's edit. The eraser splits freehand strokes at the erased point range (atomically, via one Yjs transaction) but deletes other shape types whole. Design: `docs/superpowers/specs/2026-07-29-phase9a-brushes-strokes-design.md`. Verified with the `multiplayer-sim-tester` subagent (per-user undo isolation and concurrent-erase convergence over real Hocuspocus WebSocket connections) and a full manual browser walkthrough (every preset, the highlighter's real `multiply` blend, live restyle of a selected shape, eraser split/whole-delete, undo/redo via buttons and keyboard, and two-tab undo isolation). A final whole-branch review caught and fixed 4 integration-level bugs that no single task's review could see alone: the eraser was rewriting a stroke's entire points array to Yjs on every mousemove even when nothing was actually erased (write amplification), a stuck ref could keep erasing after the mouse button was released outside the canvas, switching to the eraser/a brush preset while a shape was selected left the options bar editing the wrong thing, and restyling a selected text shape's color silently did nothing (text renders via `fillColor`, not `strokeColor`) — plus a regression the first fix round introduced (breaking live-cursor broadcast for ordinary mouse movement), caught by a scoped re-review and corrected before merge.
  - [x] **9b — Layers.** A layers panel with explicit z-ordering (a per-shape `zIndex` field, minimal-touch fractional-midpoint reordering so concurrent reorders of unrelated shapes never collide), flat grouping/ungrouping (`groupId`, one level, no nesting), a synced per-shape `locked` flag (blocks drag/delete/restyle/eraser/marquee, but never blocks a direct click to select/unlock), a local-only per-user `hiddenIds` declutter filter (never touches Yjs), and real multi-select (shift-click, marquee-drag, bulk move/restyle/delete), replacing the old flat unordered shape list and single-selection model. Design: `docs/superpowers/specs/2026-07-30-phase9b-layers-design.md`. Built via Subagent-Driven Development across 10 tasks; two real issues were caught and fixed along the way — during plan-writing, a self-review caught that the first draft of the reorder logic would have renumbered every shape's `zIndex` on every drag instead of just the moved one, breaking the concurrency guarantee, fixed before implementation began; during Task 6's review, `groupShapes`/`ungroupShapes` were found reading stale React state instead of live Yjs state (inconsistent with the rest of the hook) and `groupShapes` could leave a prior group's last remaining member orphaned with a stale `groupId` when a user regrouped a marquee-selected subset of an existing group — both fixed and re-verified. Verified with the `multiplayer-sim-tester` subagent (concurrent reorders of different shapes converge to a consistent stacking order, concurrent overlapping `groupShapes` calls converge without a corrupted/partial group, and a viewer-role connection's reorder/group/ungroup/lock attempts are all rejected server-side, same as any other write) and a full manual two-tab browser walkthrough (shift-click + marquee multi-select, bulk restyle including a text shape's `fillColor`, group/ungroup with the panel's expand-to-per-member drill-down, lock blocking drag/delete while staying clickable-to-unlock, hide confirmed local-only across tabs, drag-to-reorder and the ▲/▼ buttons syncing live to a second tab, and bulk drag-move of a multi-selection).
  - **9c — Object styling — descoped.** Would have added richer per-object styling (gradients, shadows, dash patterns, corner radius, blend modes) across all shape types, plus image import/paste as a new shape type. The project was deliberately concluded at 9b instead — 9a and 9b already demonstrate the CRDT sync, authorization, and concurrency-safety patterns this portfolio piece exists to show; 9c would have been more of the same shape without teaching anything new.
